# CLAUDE.md: Project context for Claude Code

This file gives Claude Code the context it needs to work on this project without re-explanation each session.

---

## What this project is

TrueFit is an AI-powered CV and cover letter generator. Users build a skill inventory once, paste a job offer, and get a tailored CV and cover letter generated by Claude. The core constraint is that the AI never invents or inflates experience. It only selects and frames what the user has actually listed.

---

## Tech stack

- **Frontend**: React + TypeScript + Vite + TailwindCSS
- **Database and Auth**: Supabase (Postgres + Row Level Security + Edge Functions)
- **AI**: Claude API via Supabase Edge Function (`claude-sonnet-4-20250514`)
- **PDF export**: react-pdf
- **Hosting**: Vercel (frontend) + Supabase (backend)

---

## Coding conventions

- TypeScript strict mode everywhere. Do not use `any` unless absolutely unavoidable, and add a comment explaining why.
- Named exports only. No default exports except for page-level components.
- Prefer `interface` over `type` for object shapes.
- All components must be functional. No class components.
- Use `async/await`. No raw `.then()` chains.
- Error handling: always surface errors to the UI. Never silently swallow them.
- File naming: `kebab-case` for files, `PascalCase` for components, `camelCase` for functions.
- CSS: TailwindCSS utility classes only. No custom CSS files unless unavoidable.

---

## File structure rules

- `src/components/ui/`: Pure presentational primitives (Button, Input, Card, Badge, etc.). No business logic.
- `src/components/profile/`: Skill builder, experience forms, education forms.
- `src/components/job/`: Job offer input and analysis display.
- `src/components/generation/`: CV output, cover letter output, export controls.
- `src/lib/prompts/`: Prompt assembly logic. This is the most sensitive part of the codebase.
- `src/lib/api/`: Supabase client only. Never put the Anthropic API key here. It lives in the Edge Function.
- `supabase/functions/generate-documents/`: The only place the Anthropic API key is used.
- `supabase/migrations/`: SQL files. Never edit these directly. Always create a new migration.

---

## Critical rules

- **Never put the Anthropic API key in the frontend.** It must stay in the Supabase Edge Function.
- **Never modify files in `supabase/migrations/` directly.** Create a new migration instead.
- **The prompt system must never fabricate skills.** See `docs/prompts.md` for the constraints.
- **Always run `npm run lint` before considering a task complete.**
- **Keep components under 200 lines.** Extract into smaller components if longer.
- **All Supabase queries must use Row Level Security.** Users can only access their own data.

---

## Supabase schema (summary)

Four main tables:
- `profiles`: User profile data (skills, experience, education, projects, interests).
- `skill_items`: Individual skill entries linked to a profile.
- `job_applications`: Job postings the user has applied to.
- `generated_documents`: CV and cover letter output, linked to a job application.

See `supabase/migrations/` for the full schema with types and constraints.

2. `supabase/migrations/`: Understand the database schema.
3. `src/lib/prompts/`: Understand how prompts are assembled.
4. `src/lib/api/supabase.ts`: Understand how data is fetched.
